# 测试提问：验证装对了没有

装完 Skill，别急着设定时任务。先用下面 5 句话在**普通对话**里试一遍，能看出它有没有按预期工作。

判定标准不是「回答得好不好」，而是**行为对不对**：该问的时候问，该拒绝的时候拒绝，不该出简报的时候不出。

## 一、首次使用（必测）

> 帮我出一期 SkillHub 技能推荐

**期望**：不抓数据、不出 HTML，**只问一个问题**：你关注哪些方向（痛点）。口径用默认值并当场告知一句，不要求你现在就答六项。

**不合格的样子**：
- 直接开始抓全站技能 → 没走引导
- 列出了几条现成的方向（比如「办公自动化、内容创作」这类）直接当默认痛点 → 这是替你做决定，重点看它有没有干这事
- 一上来甩出六个待定参数（每痛点几个 / 跨领域几个 / 冷冻几天…）→ 太重，用户还没见过成品，答不出来

## 二、用户拿不定主意（必测）

> 随便，你看着办

**期望**：只把口径设成推荐值（3 / 5 / 21 天 / 门槛 50），然后继续追问痛点，让你说几句平时在忙什么。仍然不出简报。

**不合格的样子**：
- 自己编 4 条痛点就开始跑
- 一句话不问直接出简报

## 三、口径越界（测边界处理）

> 每条痛点给我 8 个，冷冻改成 500 天

**期望**：夹到允许范围（每痛点最多 5 个、冷冻最多 365 天），并告知「8 超出范围，已按 5 记录」，然后回显整张口径表。

**不合格的样子**：照单全收，或者直接报错中止。

## 四、改口径（测对话式配置）

> 跨领域不要了，门槛降到 30

**期望**：只改这两项，其余保持不变；回显 6 项完整口径表，让用户确认。

**不合格的样子**：把其它项一起重置成默认值。

## 五、不应触发（测边界）

> 帮我看看 skillhub 上有个叫 xxx 的技能，值不值得装？

**期望**：直接回答这个问题，或建议用 `skillhub search`。**不要**开始跑推荐流程，也不要改动痛点清单。

**不合格的样子**：把单技能咨询当成「要一期简报」，吭哧吭哧抓数据。

## 六、真实运行（配好痛点之后）

配完痛点、口径，等一次定时触发，或者明确说「现在就出一期」。

**逐项对照 HTML 简报**：

| 检查点 | 怎么看 |
|---|---|
| 卡片数 | 痛点条数 × 每痛点推荐数 + 跨领域补充数，两者对得上 |
| 收藏率 | 0.1%–0.5% 量级。出现 29.73% 这种 → 乘 100 了 |
| 页脚「本期口径」 | 你设的数值，不是写死的 3 / 5 / 21 |
| 页脚「冷冻状态」 | 写了本期写入几条；若显示「未生效」→ 状态没存下来 |
| 跨领域段 | 设成 0 时整段消失，不留空标题 |
| 离线打开 | 断网也能看，样式不丢（有外链就会白屏） |

## 出问题了先看这三处

| 现象 | 多半是 |
|---|---|
| 根本没触发 | `description` 没覆盖你的说法；换个说法「出一期技能简报」再试 |
| 每次都在重新问痛点 | 状态存不下来：平台没有资料库能力时，检查 `~/.skillhub-recommender/` 有没有生成文件 |
| 每期推荐的技能高度重复 | 冷冻状态没写进《SkillHub推荐历史》，或冷冻期被设成了 0 |
