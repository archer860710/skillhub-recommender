# 输出规范：手机端单文件 HTML 简报

简报是主产物。对话里的 200 字摘要只是路由，不许贴源码。

## 硬性要求

| 项 | 要求 | 为什么 |
|---|---|---|
| 单文件 | 一个 `.html`，CSS 与 JS 全内联 | 手机 App 的产物预览离线打开，外链会白屏 |
| 零外部引用 | 不得出现 `src="http…"` / `href="http…"`（报告链接除外） | 弱网、内网、飞行模式都要能读 |
| 视口 | `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">` | 否则手机上字小到看不清 |
| 字体 | 系统栈 `-apple-system, BlinkMacSystemFont, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif` | 不下载字体，秒开 |
| 正文 | 16px，行高 1.7 | 触控友好 |
| 容器 | `max-width: 720px` 居中，左右 16px 内边距 | 手机上不贴边，平板上不拉太宽 |
| 双主题 | `@media (prefers-color-scheme: dark)` 覆盖 CSS 变量 | 深色手机不刺眼 |
| 表格 | **不使用 Markdown 表格**，一律卡片 / 列表 | 表格在手机上必横滚，是最大阅读杀手 |

## 页面结构（从上到下只有四块）

```
header (sticky)   标题 + 日期 · 第 N 期
stats             4 个数字卡：扫描数 / 痛点推荐 / 跨领域补充 / 冷冻剔除
                  （2×2 排布，≥560px 自动变 4 列）
digest            本期速览 3-5 行，左侧 3px 强调色边条
section 痛点推荐   每条痛点：分组标题（彩色竖条）+ 卡片
section 跨领域补充 卡片，中性灰序号，各带领域标签；条数为 0 时整段省略
footer            生成时间 / 数据来源 / 推荐门槛 / 本期变化 / 冷冻状态 / 本期口径
```

**卡片条数不写死**：每组张数 = 偏好里的「每条痛点推荐数」（默认 3），跨领域段张数 = 「跨领域补充数」（默认 5）。下文出现的 `3` / `5` 只是默认值，渲染前先读《SkillHub推荐偏好》。

## 卡片字段（顺序固定，不许缺项）

```
① 序号徽标（每痛点 ≤3 张用 ①②③；>3 张改用 1 2 3 4 5，别硬套圈码）
   技能名                    17px 加粗
   技能ID（slug）            等宽字体 12px
标签行：分类 · 收藏 N · 收藏率 X% · 全站 #R
这是什么        （2-3 句，讲清它是什么、干什么用）
解决什么问题    （用户的痛处）
用在哪          （典型场景）
推荐理由        （≤100 字）
风险提示        （需 API Key：是/否 ｜ 安全审核：benign / 未审核）
命令条          skillhub install <slug> --dir <用户 skills 目录>  [复制]
对话安装        或对话安装：「根据 SkillHub 安装 <名>（技能ID：<slug>）」
```

`--dir` 不许默认成某个产品的路径（比如 `~/.workbuddy/skills/`）。按用户实际所用 Agent 填；不确定就用对话安装那条，让 Agent 自己找目录。

`收藏率` 直接显示接口 `star_rate` 的原值（`0.30%` 这种），**不要乘 100**。

## 复制按钮

模板已内置事件委托实现：

1. 优先 `navigator.clipboard.writeText`
2. 不可用时（部分 WebView / 非 https 上下文）选中文本并提示「长按复制」
3. 点击后 1.4s 内显示「已复制」

**不要**用 `onclick="copyText(...)"` 内联写法 —— 生成器容易把引号写坏。

必查四项：

## 页脚必写内容

| 字段 | 内容 |
|---|---|
| 生成时间 | `YYYY-MM-DD HH:mm` |
| 数据来源 | 四路抓取说明 + 去重后数量 + 全站总量与覆盖率 |
| 推荐门槛 | 收藏数门槛值 + 本期池内通过率（通过数 / 池子数） |
| 本期变化 | 新上榜 / 名次大幅上升；首期写「首期执行，无对比基准」 |
| 冷冻状态 | 本期写入历史的技能数 + 下次解冻时间；**若文档写不进去，必须写「本期冷冻未生效」** |
| 本期口径 | 每痛点 N 个 / 跨领域 M 个 / 冷冻 X 天 / 收藏数门槛 Y —— 让用户一眼看到这期是按什么标准出的 |
| 数据缺失 | 若某路抓取失败，注明缺失范围 |

## 反例（别犯）

- ❌ 用 Markdown 表格输出榜单 → 手机横向滚动
- ❌ `<link href="https://fonts.googleapis.com/...">` → 内网白屏
- ❌ 收藏率写成 `29.73%` → 口径错 100 倍
- ❌ 卡片只写技能名 + 一句话 → 用户不知道它能干什么、怎么装
- ❌ 把「潜力 Top10」「上升榜」做成独立区块 → 用户明确要求删除，只留四块
- ❌ 把 3 张 / 5 张、21 天、门槛 50 当成常量写进模板 → 用户改了口径后简报还是老样子
