# 新用户第一次用：完整交互推演

> 这份文档回答一个问题：**一个人装好这个 Skill 之后，接下来到底会经历什么。**
> 时间轴、每步用户看到什么、后台发生什么、哪里会卡住，都写在这里。
> 下文样本用户「小林」和他的痛点都是虚构的，但用到的技能、收藏数、收藏率全部来自 2026-10-23 的真实接口数据。

## 时间轴

| 时刻 | 发生什么 | 用户看到 |
|---|---|---|
| T+0 | 装完 Skill | 没有变化，也没有任何提示 |
| T+2min | 新建定时任务，粘贴提示词 | 一条任务，未触发 |
| 周一 12:00 | 首次触发 | **一段提问，不是简报** |
| 周一 12:40 | 用户回复痛点 | 一张确认表 + 一句「等下期」 |
| 周四 12:00 | 第二次触发，真正出刊 | HTML 简报 + 200 字摘要 |
| 随时 | 改口径 / 加减痛点 | 改完回显整张配置表 |

**关键预期：装完当天不会拿到任何推荐。** 最快也要等到配置完成后的下一个排期点。这是设计使然——不先问清你的痛点，出来的东西就是作者的口味。

---

## 阶段 0：装完那一刻（T+0）

用户执行 `skillhub install skillhub-recommender --dir ~/.xxx/skills/`，或者把仓库目录拷进 skills 目录，重启 Agent。

**会发生什么：什么都不会发生。** 没有欢迎语，没有自动配置。Agent 只是在后续对话里多了一个可被触发的能力。

**⚠️ 卡点 1：用户不知道下一步该干什么。**
Skill 装好只是「能力就位」，要它持续产出必须再建一个定时任务。这一步 README 里写了，但 Agent 不会主动说。用户很可能装着装着就忘了。

常见自救路径：在对话里问「这个 skill 怎么用」——这时 Agent 读 SKILL.md 的「两种用法」，会告诉他去粘 `references/task-prompt.md`。

---

## 阶段 1：建定时任务（T+2min）

用户打开所用 Agent 的定时任务/自动化面板，新建一条，把 `references/task-prompt.md` 分隔线以下的全部内容粘进「任务内容」，频率填「每周一、周四 12:00」，保存。

这段提示词是自包含的——不依赖仓库里任何其它文件，所以单独复制给别人也能跑。

**后台动作：无。** 任务只是排在那儿，等下一次触发。

---

## 阶段 2：首次触发（周一 12:00）

**判定：情况 C —— 定时触发，但痛点清单不存在。**

Agent 按第〇节判断走「首次引导」，**不抓数据、不出简报、不建 HTML**，只输出第七节那段话术，然后结束。

用户手机收到一条通知，点开看到的是：

```
第一次运行，需要你先定两件事，一条消息一起回就行。

【一】痛点：你希望这个助手重点帮你解决哪些方向的问题？一行一条，建议 3-6 条。
不知道怎么表达？下面就当词库看（只是举例，不是替你选好的，也不是优先级）……

【二】简报口径：下面都是可改的，不回复就按括号里的推荐值走。
· 每条痛点推荐几个技能：3 个（可 1-5）
· 另外补几个跨领域技能：5 个（可 0-10，填 0 就只要痛点推荐）
……

【省事版】口径懒得想，就直接回「口径默认」—— 六项全按推荐值走。
但痛点必须你自己给，我不替你猜方向……
```

**⚠️ 卡点 2：第一次推送里没有简报。**
用户对「技能推荐」的预期是一份清单，收到的却是一份问卷。如果他不仔细看，会以为任务坏了。

这一条没法两全：云沙箱无人值守，问不了当场。但话术开头可以更直白一点——**先说明「这是配置，不是失败」**，再说要问什么。现在的开头「第一次运行，需要你先定两件事」勉强够，但没点明「本期不出简报」。

---

## 阶段 3：用户回复（周一 12:40）

小林把问卷回过来了：

> 1、表格和报表，每个月要做很多 Excel 汇总，还有 Word 报告
> 2、视频剪辑，拍完的素材要整理、要配音字幕
> 3、学英语，想看英文资料、背单词
> 4、小红书文案，写完总觉得一股 AI 味
>
> 口径默认

顺序其实是反的（先给了痛点再说口径默认），但没关系——解析规则允许任意顺序、任意完整度。

---

## 阶段 4：写入 + 确认

**后台动作：**

1. 写《SkillHub痛点清单》（本地无云文档能力则写 `~/.skillhub-recommender/痛点清单.md`）：

```
# SkillHub 痛点清单
| 序号 | 痛点 | 关注点 / 场景说明 | 添加日期 | 最近修改 |
|---|---|---|---|---|
| 1 | 表格与报表 | Excel 汇总、Word 报告 | 2026-10-26 | — |
| 2 | 视频剪辑 | 素材整理、配音字幕 | 2026-10-26 | — |
| 3 | 学英语 | 读英文资料、背单词 | 2026-10-26 | — |
| 4 | 小红书文案 | 去 AI 味、口语化表达 | 2026-10-26 | — |
更新时间：2026-10-26 12:40
```

2. 写《SkillHub推荐偏好》，六项全填默认值 + 「期望执行频率：未设置」。
3. **不建**推荐历史、候选池快照——等第一次真出刊时才建。

**用户收到的回复：**

```
已记下 4 条痛点 + 口径默认值（每痛点 3 个 / 跨领域 5 个 / 冷冻 21 天 / 收藏门槛 50）。

下个排期点（周四 12:00）会出第一期。想现在就看效果的话，说一句「现在就出一期」。
```

第四行的「其实可以现在就出」——用户在阶段 2 的话术里看不到这句，只能靠 Agent 当场补。这是**唯一能缩短等待的出口**。

**⚠️ 卡点 3：配置完到出刊之间的空窗。**
周一定的事情，周四才见到成果，中间三天没有任何反馈。新人最容易在这个窗口流失。

## 阶段 5：首次出刊（周四 12:00）

**判定：情况 B —— 有痛点，出简报。**

后台六步：

## 阶段 6：用户改口径（随时）

> 每条痛点改 2 个，跨领域不要了

**后台动作：** 只改被点名的两项，其余四项原样保留。

```
| 配置项 | 值 | 可调范围 |
|---|---|---|
| 每条痛点推荐数 | 2 | 1-5 |
| 跨领域补充数 | 0 | 0-10 |
| 跨领域是否要求不同领域 | 是 | 是 / 否 |
| 冷冻期（天） | 21 | 0-365，0 关闭 |
| 收藏数门槛 | 50 | 0-1000 |
| 痛点覆盖上限 | 6 | 1-20 |
| 期望执行频率（用户设定） | 未设置 | 仅记录，不生效 |

跨领域那段下期起整段不出现。
```

如果他说「只推免费的」——这项目前不支持，要如实说，不能假装改了。

---

## 阶段 7：第二期（下周一 12:00）

这期开始，冷冻与增速两套机制同时生效：

- 上期 12 个技能全部在 21 天冷冻期内 → 直接剔除，不会重复刷脸
- 有上期快照了 → 上升榜开始工作：对比本周与上周同技能的 `stars`，`Δ ≥ 20` 或增长 ≥ 30% 的补入候选池
- 期号 = 历史里不同推荐日期数 + 1 = **第 2 期**
- 页脚「本期变化」终于有内容：新上榜 N 个 / 名次大幅上升 N 个

## 会走偏的几种问法

| 用户说 | 正确反应 | 不合格的反应 |
|---|---|---|
| 「随便，你看着办」 | 只把口径设成默认，然后追问痛点 | 编 4 条通用痛点开始跑 |
| 「你帮我定几条痛点」 | 只能基于他此前说过的话提炼，逐条回显确认 | 直接给一套「办公/创作/数据/生活」 |
| 「全领域均衡」 | 清单里写这一条标记，按分类各取头部 | 当普通痛点去匹配 |
| 「改成每周三晚上」 | 记录期望频率 + 说明要自己在 Agent 里设 | 回复「已帮你改好时间」 |
| 「加个全站 Top 10」 | 听他的，加在四块之后 | 拒绝，说「只输出四块」 |
| 「现在的收藏率怎么才 0.3%」 | 解释这是全站真实量级，0.2% 以上已优秀 | 乘 100 改口说 0.3 是错的 |

---

## 一句话总结

装好之后，用户真正需要做的只有一件事：**回答它问的问题**。
痛点、条数、冷冻、门槛全由他定，Skill 只负责记住、抓数据、挑出来、排版成手机上能读完的样子。
剩下的时间它就按排期自己跑，每期换一批没见过的。
