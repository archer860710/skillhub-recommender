# skillhub-recommender

> 从 SkillHub 的十万级技能库里，按你的痛点挑出真正值得装的那几个。

一个 Agent Skill。装给任意支持 SKILL.md 的助手（WorkBuddy / Claude Code / Cursor / Codex / Qwen / OpenClaw …），它就能定期给你出一份技能简报，输出为手机上能读完的单文件 HTML。

推几条、怎么组成，由你自己定。首次运行时它会问你两个问题：**你关注什么方向**，以及**简报要什么口径** —— 每条痛点推几个、额外补几个跨领域的、推荐过的技能多久不重复。默认是「每痛点 3 个 + 跨领域 5 个 + 冷冻 21 天」，但这只是没回答时的兜底值，不是写死的规则。

## 为什么不是「按下载量排行」

因为下载量会骗人。

| 现象                         | 数据                 |
| -------------------------- | ------------------ |
| 下载榜 Top200 的收藏率中位数         | **0.03%**          |
| 某编程类技能                     | 下载 381 万，收藏 **16** |
| 下载榜 Top100 ∩ 收藏榜 Top100 重叠 | **仅 38 个**         |

下载量含企业预装与批量分发，前排大量是"被装上了但没人用"的技能；而真正收藏率高、口碑好的技能，下载量常常只有几万，永远爬不进下载榜。

本 Skill 以 **收藏数（stars）** 为主信号，四路抓取（下载榜 + 收藏榜 + 分类头部 + 增速候选），先筛出 240–450 个候选，再按你的痛点挑。全站到底有多少个技能、分几个类，每期都从接口现取，不在代码里写死。

## 四个不那么显然的设计

**1. 痛点不写在提示词里，存在云端文档，用对话管理**

```
查看我的痛点
增加一个痛点：财务报表分析
把第 2 条改成：自媒体选题与文案
删除第 3 条
```

第一次运行它会问你要关注什么方向（附 5 大类词库，不知道怎么说就直接描述你平时在忙什么，它来提炼）。

**痛点必须由你说，工具不替你预设。** 你说「随便」「你看着办」，它只会把口径设成默认值，然后接着问你痛点 —— 毕竟一份按别人痛点挑出来的简报，对你没什么用。实在不想按方向挑，可以明确说「全领域均衡」，它就不设痛点，改按分类各取头部。注意：只有你亲口这么说，它才会切到这个模式。

**2. 简报口径也不是硬编码的，同样存在云端、同样用对话改**

| 配置项 | 默认 | 可调 |
| --- | --- | --- |
| 每条痛点推荐数 | 3 | 1–5 |
| 跨领域补充数 | 5 | 0–10（填 0 就整段不要） |
| 跨领域是否来自不同领域 | 是 | 是 / 否 |
| 冷冻期 | 21 天 | 0–365（0 = 关掉去重） |
| 收藏数门槛 | 50 | 0–1000 |
| 痛点覆盖上限 | 6 | 1–20 |

```
每条痛点改 2 个
跨领域不要了
冷冻改成 30 天
门槛降到 30
恢复默认
```

改完它会回显整张表。默认值只是「你没说」时的兜底，不是这套工具的主张。

**3. 21 天冷冻去重**

推荐过的技能 3 周内不再出现（天数可改）。满期且仍居候选池收藏数前 20% 才可复审再推，推后重新冷冻。榜单不会每期都是同一批脸。

**4. 增速候选池**

榜单按累计值排序，头部很稳、长尾爬得极慢，所以"名次还不高但正在蹿升"的技能只能靠做差捞出来：与上期快照比，收藏数增量 ≥ 20 或增长率 ≥ 30% 的直接进池。

## 安装

```bash
skillhub install skillhub-recommender --dir <你的 skills 目录>
```

`--dir` 换成你所用 Agent 的 skills 目录：

| Agent       | 目录                     |
| ----------- | ---------------------- |
| WorkBuddy   | `~/.workbuddy/skills/` |
| Claude Code | `~/.claude/skills/`    |
| Cursor      | `~/.cursor/skills/`    |
| Codex       | `~/.codex/skills/`     |
| QoderWork   | `~/.qoderwork/skills/` |

或者直接把本仓库目录拷进 skills 目录，重启 Agent 即可。不想找目录的话，也可以直接对 Agent 说「根据 SkillHub 安装 skillhub-recommender」，让它自己放。

**先验证装对了没有**：照 [`references/test-prompts.md`](references/test-prompts.md) 里的 5 句话问一遍。重点是看它在你要痛点之前，会不会自己编几条顶上 —— 会的话说明装的是旧版。

**升级**：

```bash
skillhub install skillhub-recommender --dir <你的目录>   # 覆盖安装即可
# 或用 git：
git -C <你的目录>/skillhub-recommender pull
```

升级只替换 `SKILL.md` 和 `references/`，不碰你已有的痛点清单与偏好文档。

## 不适合拿它做什么

- **搜单个技能**：直接 `skillhub search <关键词>`，比跑一期简报快得多
- **查某个技能的详情**：`https://skillhub.cn/skills/<slug>`，或看接口返回
- **装技能**：`skillhub install <slug>`，简报里只给命令，不动你的环境
- **找遍全站**：每期只扫 240–450 个头部，覆盖率约 0.1%。它保证「推的靠谱」，不保证「不漏」

## 两种用法

### A. 装成定时任务（推荐）

只有定时任务才能持续产出。把 [`references/task-prompt.md`](references/task-prompt.md) 的全文粘进你所用 Agent 的定时任务内容里，频率自定（每天、每周一次、每周两次都行）。

那段提示词是**完整自包含**的，不依赖本仓库文件，单独发给别人也能跑。

> 首次触发不会出简报，而是先问你痛点和简报口径 —— 云沙箱无人值守，问不了当场，这是设计如此。

### B. 会话内直接跑一期

跟 Agent 说「用 skillhub-recommender 给我出一期技能简报」，它按 `SKILL.md` 的工作流抓数据、挑技能、产出 HTML。

## 产出长什么样

```
① 简报头部    日期 + 扫描概况
② 痛点推荐    每条痛点 N 张卡片（默认 3）
③ 跨领域补充  M 张（默认 5，默认跨不同领域；M=0 则省略）
④ 页脚        数据范围 / 门槛口径 / 本期变化 / 冷冻状态 / 本期口径
```

每张卡片：名称 + 技能ID + 分类 + 收藏数 + 收藏率 + 全站排名 → 这是什么 → 解决什么问题 → 用在哪 → 推荐理由 → 风险提示（需 API Key / 安全审核）→ 可复制的安装命令。

模板在 [`assets/briefing-template.html`](assets/briefing-template.html)，单文件、零外链、深浅双主题。

## 发布（维护者）

一份源，三处分发：

```bash
python scripts/validate.py                          # 预检
python scripts/publish.py --dry-run                 # 演练，不发请求
python scripts/publish.py --bump patch --changelog "修正收藏率口径"
python scripts/publish.py --only github             # 只推 GitHub
```

三条通道的细节见 [`references/publishing.md`](references/publishing.md)。Token 走环境变量，不写进文件。

## 已知的坑

- **收藏率字段已经是百分数**：`0.2973` 就是 `0.30%`。乘 100 会写出「收藏率 29.73%」这种离谱数字。
- **1/3/5/21/50 只是兜底值**：这五个数字散落在提示词、模板、校验里，任何一处被当成常量，用户改了口径就会失效。改代码前先搜一遍。
- **覆盖面只有 0.1%**：全站约 19.5 万（2026-10 实测，持续增长），每期扫 240–450 个头部。简报页脚必须如实标注覆盖率，不能让人以为扫了全站。
- **云端文档写不进去时**，冷冻去重会失效。此时简报页脚必须写「本期冷冻未生效」——静默失效比没有功能更糟。
- **任务改不了自己的排期**：频率由 Agent 侧管，Skill 只能记录用户的期望值，不能声称"已改好"。
